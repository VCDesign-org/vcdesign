# VCDesign Value Asymmetry Model: upside は伝播可能にする。downside は伝播させない。

## Status

**Design principle / Reading aid — not authority.**

このドキュメントは、VCDesign の名にある「価値の継続（Value Continuity）」を、
**価値を壊さないこと（下を閉じる）**と**価値が次の価値を生むこと（上に開く）**を
同じ判断記録の上で同時に扱うこととして定義する設計原則である。
その中心原則を **Value Asymmetry Principle** と呼ぶ。

> upside は伝播可能にする。downside は伝播させない。

仕様上の権威は `core.yaml`（`value_accumulation` / `downside_containment` / `value_asymmetry`）、
`policies.yaml`（`scale_gate` / `long_term_decision_gate`）、`metrics.yaml`
（`accumulation_metrics` / `containment_metrics`）にある。
フィールド定義は `schema_case.yaml` (v0.3) にあり、本文書はその読み方を固定する。

既存文書との役割分担:

- `value-tenure-model.md` — 責任の**時間軸上の性質**（点か線か）を定義する文書
- `value-asymmetry-model.md`（本文書）— 価値の**分布の形**（上下の裾をどう扱うか）を定義する親文書
- `downside-containment-model.md` — 本文書の下側（裾を切る 4 機構）の詳細

---

## 1. なぜこの区別が必要か

VCDesign はこれまで、価値を**壊さない**側を中心に書かれてきた。
責任の非消失、停止経路、境界、封じ込め。これらは必要だが、それだけでは価値は継続しない。

現場でよく聞く問いがある。

> 改善したのに、なぜ人も手間も減らないのか。

多くの場合、改善が**その時点の業務**に紐づいているからである。
今の手順の 5 分を削っても、手順が変われば削った 5 分ごと消える。
削れた時間は数人に数分ずつ散らばり、どこにも積み上がらない。
その場で小さく勝っているだけなので、継続投資・継続運用の根拠にならない。

さらに、探索や試行の成功条件がたいてい「動いた」「効果が出た」という**平均**を見る条件になっている。
その改善が一回きりで終わるのか、接続されて広がっていくのかという**裾の形**は誰も見ていない。
成功条件が平均しか見ていないので、裾を持たない改善が「成功」として通り、量産される。

---

## 2. 点の改善と線の改善

`value-tenure-model.md` は、責任を点（Gate）と線（Tenure）に分けた。
本モデルは同じ区別を、責任から**価値と投資**に広げる。

| 観点 | 点の改善 | 線の改善 |
|---|---|---|
| 紐づく先 | その時点の業務・手順 | 業務・担当・技術の変化をまたぐもの |
| 業務が変わると | 無効化され、何も残らない | 記録・標準・根拠・接続・技能が残る |
| 成果の効き方 | その場に散らばって消える | 再利用のたびに次の成果を生む |
| 完成条件 | 動いた時点 | 変化をまたいで維持・更新できる状態 |
| 投資の根拠 | 一回ごとに説明が必要 | 次の適用が安くなることが根拠になる |

判定の問いは一つである。

> **業務が変わったら、この改善の何が残るか。**

何も残らなければ点の改善である。残るものがあり、それを保有し続ける主体がいれば線の改善である。
VCDesign ではこれを `schema_case.residual_assets` として宣言する。

---

## 3. 上に開く：残るものと裾の兆候

VCDesign における上振れは、成長施策やマーケティングの話ではない。
**業務が変わっても残るもの**が、再利用・接続されることで、次の価値を生むことである。

### 残るものの種類（`residual_asset_kinds`）

- **record** 記録（履歴・構成・判断ログ）
- **standard** 標準（手順・受入条件・構成の型）
- **basis** 判断の根拠（`re_derivation_basis` を含む）
- **connection** 接続（他の章・システム・主体とのつながり）
- **capability** 技能・能力（復旧・変更を実行できる力）

保有者のいない資産は残らない。`residual_assets` の各項目は `holder` を持つ。

### 裾の兆候（`tail_signals`）

ここでいう裾の兆候とは、平均的な改善量ではなく、再利用によって大きく広がる兆候のことである。

大きく広がりうるかは、技術指標ではなく業務で観察できる事実で見る。

| 兆候 | 観察できる事実 |
|---|---|
| `reuse_cost_decline` | 同じ仕組みを別の場所に入れるコストが、回を追って下がる |
| `unsolicited_pull` | 依頼していない部署・主体から「うちでも使いたい」が来る |
| `output_as_input` | 成果が別の判断・システムの材料として使われ始める |
| `value_per_connection` | 利用やデータが増えるほど、一件あたりの価値が上がる |

開始時に「どの兆候が出れば広げるか」を宣言し、レビュー時に観測する。
平均的な効果（`average_outcome`）とは独立に記録する。

## 4. 下を閉じる：裾を切る

下側は `downside-containment-model.md` に定義する 4 機構
（isolate / cap / revalidate / deconcentrate）と、可逆性の記録で扱う。
要点は、下振れを予測することではなく、**内部での増幅・伝播を切る**ことである。

---

## 5. 上と下をつなぐ

上下を別々に語ると衝突する。上振れの手法は「つなげ」と言い、下振れの手法は「切れ」と言う。
同じ接続が上下両方の裾を生むからである。VCDesign は両者を次の原則でつなぐ。

### 変更に賭けられる回数は、復旧能力で決まる

復旧できる範囲でしか変更に賭けない。復旧能力を上げることが、賭けられる回数を増やす。
「壊れるのが怖くて触れない」システムは、下を閉じる能力が足りないために上にも賭けられない状態である。
**下を閉じる仕組みは守りではなく、上に賭けるための原資である。**

### 宣言した上限が、試行の予算になる

`blast_radius.max_loss` を宣言した分だけ、小さな賭けを打てる。
上限を宣言しない判断は、失敗の大きさが分からないので試行の回数も決められない。

### 結論ではなく根拠を流す

境界を越えて流れるものが根拠であれば、再利用（上）は保たれる。
結論をそのまま引き継がなければ、誤りの増幅（下）は切れる。
知見と判断は上下が同じ経路を共有する流れであり、ここが両立の難所になる。

## 6. 判断ルール（scale_gate）

小さく始めた判断を広げるとき、根拠は平均的な成功ではなく裾の兆候である。

| 平均的な効果 | 裾の兆候 | 判断 |
|---|---|---|
| あり | あり | 宣言した max_loss と復旧能力の範囲で拡大（scale_go） |
| あり | なし | 小さく留めるか終了（keep_small_or_retire） |
| なし | あり | 形を変えて小さく再挑戦（reframe_and_retry_small） |
| なし | なし | 終了（retire） |

二行目が最も重要である。**成功したのにやめる、または広げない**判断を正当化する根拠がないことが、
点の改善が増え続ける原因になっている。

拡大の前提（`policies.yaml scale_gate.required_before_scale`）:
観測された兆候、宣言された残るもの、拡大後の最大損失、拡大後も復旧できること、人間の最終判断者。

---

## 7. 観測

| 側 | metric | 見ていること |
|---|---|---|
| 上 | `one_shot_improvement` | 業務変更で改善が消えた（Δ として扱う） |
| 上 | `tail_signal_absent_on_success` | 成功したが広がる兆候がない |
| 上 | `reuse_cost_trend` | 再利用のコストが下がっているか |
| 結合 | `scale_beyond_recovery` | 拡大が復旧能力を超えていないか |
| 下 | `containment_metrics` 一式 | 下振れの裾が増幅・伝播する条件 |

`one_shot_improvement` を Δ として扱うのが本モデルの要である。
VCDesign はもともとズレを観測する仕組みであり、「改善が消えた」をズレとして検知できれば、
上振れは既存の枠組み（Δ → RCA → Fix / Reframe / Defer / Retire）にそのまま乗る。
