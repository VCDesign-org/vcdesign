Value Continuity Design · v2

VCDesign

VCDesign は、Value Continuity を判断と責任の面から実装する方法論です。

Value Continuity とは、

変化や失敗があっても、次の価値を生み出せる状態を継続すること。

その中心原則（Value Asymmetry Principle）は、

Upside は伝播可能にする。Downside は伝播させない。

出典：value-continuity/value-continuity README（定義と原則の正本）

「伝播可能にする」は、自動で広げることではありません。良い結果が次へ広がれる道を開いておき、実際に広げるかどうかは判断（Expand）で決めます。

VCDesign が定めること

誰が、何を根拠に、6つの判断のどれで閉じ、残ったものを誰が持ち続けるか。

Value Continuity の定義と原則は正本にあり、VCDesign では定義し直しません。VCDesign は、それを現場の判断と責任の記録として実装し、検査できる形にします。

判断の所在と責任の帰属が説明できない状態では、実装を始めません（実装境界事前定義）。

芯の6つ

芯VCDesign が定めること
Δ宣言した期待（前提と価値）との差。向きを持つ。Negative Δ は伝播させず、Positive Δ は伝播可能にする
責任owner、人間の最終判断者、担当交代をまたぐ継続保有（点の責任は開始、線の責任が維持）
境界損失は止め（containment）、根拠は通し（basis_flow）、結論は確かめ直す（revalidation）
判断6語（Proceed / Expand / Limit / Reframe / Defer / Retire）だけを使い、判断ゲート1つで閉じる
宣言案件ごとに、残すもの（保有者付き）、広がりの兆候、最大損失、可逆性、依存先
指標5原則（残す・見つける・閉じる・試す・伝える）の順に並ぶ芯の17件

AI 統制（AI は最終責任を持たない、LLM の配置、時間定数の分離、エージェントの実行ゲート）は、芯の外に置いた VCDesign 固有の拡張です。

5原則の順に確かめる

Value Continuity の5原則は、この順番に意味があります。VCDesign の判断ゲートも、指標も、この順に並んでいます。

  1. 残す業務・担当・技術が変わっても残るものを、先に決める
  2. 見つける平均的な改善量ではなく、再利用によって大きく広がる兆候を見る
  3. 閉じる悪い広がりは予測せず、境界で止める
  4. 試す戻せる範囲で変更する
  5. 伝える結論ではなく、根拠を次の判断へ渡す

各原則の一文は正本 README §3 から引用しています。

確認を終えたら、人間が6語のいずれかで判断を閉じます。詳しくは判断へ。

どこから読むか

  • 製造・OT/IT の現場で

    設備データの収集、担当交代、工場の AI エージェント。架空の現場で、宣言と判断がどう記録されるかを見る。

  • AI エージェントを業務に入れる

    能力は権限ではない。4つのループ、LLM の置き場所、実行前のゲート、停止の設計。

  • 思想から読む

    Value Continuity の定義、非対称の原則、5原則、判断の6語を正本の言葉で。

  • 仕組みを知る

    芯の6つを1ページで。5原則ごとに、VCDesign のどの仕組みで実装しているか。

  • v1 を使っていた

    v2 は v1 と互換性がありません。語彙と記録の読み替え表と、旧ページの行き先。

  • 関連プロジェクト

    VC-AD、TDDD、VMS、Value Review、Re-derivation Layer、Continuity Claim Protocol、idk-lamp.org。

Specs を参照する

このサイトは説明です。規範は github.com/VCDesign-org/vcdesign の仕様にあります。設計支援や判断支援、コード生成のために生成 AI へ渡すときは、GitHub の YAML をそのまま渡すのが最短です。

VCDesign v2 の authority は次の3ファイルです（Core, Metrics, Policies）。

  • specs/core/core.yaml — Δ・判断・宣言・責任・境界の規則
  • specs/core/policies.yaml — 判断ゲート、責任・説明・停止の規則、AI 拡張
  • specs/core/metrics.yaml — 5原則の順に並ぶ芯の指標

適合判定の起点は specs/core/axioms.yaml（A1〜A5）です。全体の地図は Specification Map、正本との対応表は implementation.md にあります。
