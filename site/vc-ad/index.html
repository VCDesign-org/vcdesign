VC-AD

Value-Continuous AI Development。実装は AI に任せても、判断と責任の芯は人間が持つための開発プロトコルです。

VCDesign は法則であり、VC-AD はその現在技術水準における具体化である。

出典：VCDesign README

VC-AD がすること

AI エージェントにコードを書かせるとき、何を決めたのか、何をしてはいけないのか、どこでつながるのか、どのファイルに適用するのかを、リポジトリの中の YAML として渡します。AI はその範囲の内側で実装し、範囲を守っているかを道具で確かめます。

VCDesign の言葉でいえば、人間が閉じた判断で許可された範囲（公理 A2）を、開発の現場で機械が読める形にしたものです。

リポジトリ

規範は VCDesign-org/architecture-yaml-protocols にあります。使い方と最新の構成は、リポジトリの README を参照してください。2026年9月時点の主な構成は次のとおりです。

ディレクトリ役割
decisions/Why / What。アーキテクチャ上の判断、方針、技術選定
contracts/Must / Must Not。言語に依存しない方針（資源、副作用）と入出力の契約
connections/How / Interface。構成要素の間の接続、データの流れ、API の契約
components/Where。上の規則を実際のコード（ファイルパス）に割り当てる
tools/Gatekeeper。契約が守られているかを検査する道具
