周辺

関連プロジェクト

VCDesign の周りにある実践や道具です。それぞれの規範は各リポジトリにあり、VCDesign の仕様ではありません。

状態の表示：v2 と整合は v2 の語彙と矛盾しないもの、v1 の語彙は v1 の語彙で書かれたままのものです。v1 の語彙の読み替えは移行表を参照してください。

  • VC-AD

    別リポジトリで更新中

    AI による開発で、判断・契約・接続・適用範囲を YAML として渡し、人間が設計と責任の芯を持つための開発プロトコル。

    「VCDesign は法則であり、VC-AD はその現在技術水準における具体化である」（VCDesign README）。

  • TDDD

    独立した実践記録

    TODO Driven Development。生成 AI の時代に、コードではなく判断を残すための開発の運用記録。

    tddd-playbook

  • Value Review

    v1 の語彙

    実装の前に、どの価値をどの境界の内側で守るかを決めるレビューシート（L1〜L4）。v2 では、判断ゲートと正本の Review Output が同じ役割を担います。

    vcdesign-value-review

  • VMS / VMS Marketing

    v1 の語彙

    経営やマーケティングの悩みを、ループ・境界・判断に翻訳して、責任と価値の継続を設計する運用プロトコル。

    vms · vms-marketing

  • Re-derivation Layer

    v2 と整合

    ロボットや設備の動作を、後から責任と業務上の意味として説明できるようにする層（物理 AI と OT の境界）。v2 の「伝える」の一つとして用語集にも位置づけられています。

  • Continuity Claim Protocol

    v2 と整合

    別の組織やエージェントをまたいで越境するとき、識別・境界・権限・署名を先に宣言するためのプロトコル。境界パターンの external_crossing が参照しています。

  • idk-lamp.org

    v2 と整合

    AI に「分からない」ランプを持たせる、日常の場面からの入口。境界の判定で、判定できないときは unknown として止めて上げる、という考え方を身近な話で説明しています。
