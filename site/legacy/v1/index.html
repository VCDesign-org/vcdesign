Agent Era

能力は権限ではない

VCDesignは、モデル単体のAI時代だけでなく、ツール実行・連鎖操作・長時間動作を行うAIエージェントの時代にも適用できます。

エージェントが高性能になるほど、「能力があるから任せる」という判断が増えます。しかし実行境界・責任者・停止条件を設計しないエージェントは事故源になります。

5層構造（外部説明フレーム）

L1

Model Layer

推論・解釈・提案（出力のみ、実行なし）

L2

Agent Layer

実行境界・ツール制御・Multi-Agent協調

L3

Responsibility Layer

誰が何を保持し、誰が最終判断するか

L4

Time Layer

時間スケールの分離。速いループが遅いループを上書きしないための構造

L5

Human Sovereignty Layer

人間が最終的に介入・停止・説明できる主権

下位レイヤーの能力は、上位レイヤーの統治構造なしに拡大してはなりません。
詳細は specs/core/agent-era-model.md を参照してください。

Gate / Tenure

承認は、保有ではない

いま業界が語る「責任」は、承認の一点に錨を下ろしています。「今、これは正しいか？」そのゲートは重要です。しかし、それは点にすぎません。

価値が失われるのは、その後です。承認した人が異動する。なぜその判断だったのか、誰も再導出できなくなる。ドリフトは、誰も見ていない間にこそ起きる。自律運用が進むほど、「いま誰が持っているのか」という問いは消えるのではなく、鋭くなります。

Gate — 点の責任 Tenure — 線の責任
問い「今、これは正しいか？」「誰が持ち続け、交代と時間を生き延びるか？」
生きる場所承認の瞬間承認後のすべての日々
壊れ方承認の省略・形骸化保有者の離脱、根拠の散逸、儀式化したレビュー

VCDesignが加えるのは、オーナーの名指しではありません（それはRACIや変更管理が既にやっています）。後任が判断を再導出できるか——守っている価値、責任の継承履歴、判断を再構成するための根拠、そしてカレンダーではなく「何が起きたら見直すか」の条件を、構造として持つことです。

承認は責任の開始であり、保有がそれを維持します。自律運用はこれを不要にするのではなく、必要にする条件そのものです。
詳細は specs/core/value-tenure-model.md、実例は specs/examples/custody-handover.md を参照してください。

導入診断

Maturity Profile

組織・システムがAIガバナンスの各層においてどの段階にあるかを診断するフレームワークです。5層それぞれを4段階で評価します。

Level 意味
Unstructured構造なし。設計上の対応物が存在しない
Defined文書上は存在するが、実運用では強制されていない
Enforced実運用で機能しており、違反時に制御が発動する
Governed監査・改善・再評価まで回っており、継続的に維持される

診断例：

Model Layer:          Enforced
Agent Layer:          Defined
Responsibility Layer: Unstructured  ← ここが全体の限界
Time Layer:           Defined
Human Sovereignty:    Enforced

最も低いレベルの層が、システム全体のガバナンス限界を決めます。
詳細は specs/validation/vcdesign-maturity-profile.md を参照してください。

設計思想

VCDesign 憲法とマニフェスト

憲法（Constitution）

第1条：価値の継続 (Continuity of Value)

システムの目的は機能の維持ではなく、価値の継続である。

価値が損なわれた時、システムはΔ（ズレ）を起点として自らを変容させる義務を負う。

第2条：責任の所在 (Locality of Responsibility)

すべての振る舞いには、それを引き受ける「章（Chapter）」が存在しなければならない。

責任が不明瞭な状態（owner_missing）を放置することは、システムの終焉を意味する。

第3条：人間の主権 (Human Sovereignty)

AIと自動化は判断を助けるが、責任を持たない。

最終的な意味の確定および構造変更（Reframe / Retire）は、常に人間が主導し、説明可能でなければならない。

マニフェスト（Manifesto）

1. 章の有限性を愛せ (Embrace Finite Chapters)

章（Chapter）は不変の真理ではない。現実との乖離やΔの蓄積により、章は必ず漂流（Drifting）する。

変化は失敗ではなく、価値継続のための遷移（Reframe）の前提である。

2. Δを隠すな、徴候を祝え (Celebrate Delta Signals)

Δ（ズレ）は進化の入口である。責任メトリクスを用いて違和感を観測し、driftingを宣言せよ。

沈黙する正常よりも、観測された異常を優先せよ。

3. 過去への忠実さより、未来への一貫性を (Consistency over Legacy)

判断ログ（Decision Log）は過去の再現ではなく、「価値への接続（Purpose Linkage）」を記録するものである。

すべての判断は未来への説明責任を持つ。

4. 責任を閉じよ、さもなくば上位へ送れ (Close or Defer)

曖昧な責任はシステムを劣化させる。解決できるならFixせよ。できないならDeferせよ。

責任を持ったまま放置することを禁止する。

5. 意味のない自動化を引退させよ (Retire the Meaningless)

価値を生まない章、コード、データは維持してはならない。

継続しないこともまた、設計である。
